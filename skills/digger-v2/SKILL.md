# Digger — Biology深度研究

## 读者与写法（这一节写错，整份调研就废了）

**读者没有任何生物背景。** 他是投资人或媒体人，商科出身。

- 他知道细胞、DNA、蛋白质这些词大概指什么
- 他**不知道**线粒体内膜上发生了什么、什么叫质子梯度、什么叫 pKa、什么叫共聚物、什么叫半衰期
- 他遇到不懂的词**不会停下来查**，会直接跳过那一段，然后对整份调研的信任度下降
- 他很忙，而且要拿这份材料去跟创始人开会。所以他不只要看懂，还要能复述、能提问。一个他读完还是说不出口的概念，等于没写

**硬标准：高中生物课本里没出现过的词，第一次用的时候必须当场用一句话讲明白，或者换一个说法绕开。** 这是全文优先级最高的一条，后面不再重复。

反面例子（这些写法等于没写）：

- 「可解离的酸性基团」「庞大的疏水基团」：直接扔术语
- 「pKa 落在生理 pH 附近」：没解释 pKa 是什么
- 「共聚必然产生组成漂移」：三个术语叠一起
- 「PD 功能半衰期 4.9 天 vs 血浆半衰期 16.7 小时」：两个概念都没解释，读者无法在对话中使用这个信息

正面写法：

- 「这个分子要能在两种状态之间来回切换：一会儿带电，一会儿不带电。带电的时候溶在水里，不带电的时候能钻进油性的细胞膜。DNP 正好能做到这件事。」

### 写法六条

1. **先给结论，再给机制。**
2. **分步拆解优于大段叙述。** 机制类内容宁可多一步，不要少一步，不要因为"太基础"跳步。
3. **宁可深讲最关键的 3 个机制，也不要对 20 个点浅尝辄止。** 最关键 = 如果这里不成立，整个结论就不成立。
4. **区分"事实""推断""公司自述"**，不混着讲。
5. **承认复杂性。** 学术上有争议就直说科学界还没搞清楚，并说明争议在哪。
6. **最难的部分花最多时间。** deck 里最难懂的技术，往往就是核心竞争力所在。

### 长度和时间预算

**长度不是问题，看不懂才是问题。** 多花三句话解释一个概念，好过省下三句话让读者跳过整段。

时间预算只约束两处：**一屏摘要**要让读者在几分钟内掌握大意，**核心机制**要让他读完能复述。正文其余部分不设字数上限，但每新增一段要问它是否让科学更清楚，不是就删。篇幅过长时把次要内容折叠到附录，核心机制不得折叠。

### 语言和格式

- 中文主体，英文术语首次出现时括号标注原文
- 遵守用户 CLAUDE.md 的写作规则：不用破折号；不要每句都加粗，加粗只用于真正的关键结论；不用"总之""综上所述""值得注意的是"这类套话；不用互联网黑话
- 涉及监管、政治、国别比较时用描述性说法，讲清机制和事实，不给它贴标签
- 用户划掉的词要全文清除，不是只改他指出来的那一处，改完用关键词扫一遍确认
- 每个事实性数字（比例、金额、年份）后面标来源。无来源的数字，不写，或明确标"未核实"
- 交付形式：默认给飞书文档、PDF，或直接在对话里输出。不给用户 Markdown 文件
- 结尾永远是"下一步行动"或"还没搞清楚的问题"，并写明该向谁求证

## 这个skill要达成的结果

**科学讲清楚，是第一优先级。** 读完你的输出，用户应该能做到三件事：

1. **科学上真正搞懂**：机制每一步发生了什么、为什么是这样，能向同事复述，也能在跟创始人打电话时当场用上，不靠背术语。
2. **判断一家公司的说法**哪些有证据、哪些是推断、哪些可能夸大。
3. **知道下一步该问谁、问什么**，而不是只得到一堆知识。

第 1 条最重要。达不到就继续补，而不是凑篇幅。

**最常见的失败：用术语代替解释。** 讲了宏观结论，却略过决定结论成立与否的关键细节。

**第二常见的失败：给出读者无法使用的信息。** 一个数字如果读者不理解它的含义，他就没法在跟对方沟通时用它。写每个关键数字时问一句：读者拿这个数字去问对方，问得出来吗？

## 第0步：先搞清用户拿这份研究去干什么

别急着写背景。先从用户的话里判断（判断不出再问一句，一句就够）：

| 用户的真实目的 | 研究重点要往哪偏 |
|---|---|
| 投资/尽调 | 技术壁垒、证据强度、临床成功概率、竞品对比、红旗 |
| 写稿/做媒体 | 能对外讲的准确说法、哪些说法不能写、争议点、可引用来源 |
| 自己学习 | 概念之间的因果链、历史转折、该读哪几篇论文 |
| 解读某份材料 | 材料里每个主张对应哪层证据 |
| 公开露面：受访、对谈、上台 | 先读 `references/onstage.md`，再按它准备台上要说的那一份；台上那份材料本身走 `iceberg-evidence-doc` 的 `--talk`。其余目的不读这个文件 |

把目的写进开头第一句："这份研究用来：……"。后面所有取舍，都围着这个目的。目的也决定哪些章节适用：「观点的形成与表述」只在投资判断、写稿或公开露面时做，「交叉评审」只在完整调研时做。

## 整体流程（顺序不可颠倒）

1. **第0步**：判断用户的目的，写下"这份研究用来：……"
2. **读完用户给的全部材料**，再去查公开资料
3. **研究 + 初稿**：模式A，或模式A → 模式B
4. **自动追问**：外行读者替用户把追问问完，答案并入正文，最多 2 轮
5. **Fact Check**：对终稿逐条证伪。放在追问之后，因为追问会产生新的具体说法，这些新说法同样要被核查
6. **时效性核查**：对每个状态类事实和每个关键结论，专门再搜一轮新进展和新的反方证据。放在终稿之后，因为它要对准的是终稿里实际留下的说法
7. **交叉评审**：换一个没参与写作的模型读终稿。放在自己核完之后，否则你拿一份自己都没核过的东西去问别人，它提的质疑你也判断不了谁对
8. **交付**：一屏摘要在最前，已替你追问过的问题 + Fact Check 在末尾

## 用户自己拿到的材料，优先级最高

用户可能提供 deck、创始人通话记录、访谈纪要、邮件。**这些是比任何公开资料都强的一手来源，必须完整读完，并且在调研里充分使用。**

1. **先读完用户给的全部材料，再去查公开资料。** 不要先查完再读。
2. **创始人在通话里讲的机制细节，往往比 deck 详细得多**，而且会暴露 deck 没写的东西：真实动机、内部数据、未披露的风险。
3. **公开资料查不到，不等于不存在。** 创始人讲了而公开资料没有的，标注"来自创始人口述，未经独立验证"，但不要因为查不到就默认是假的。
4. **冲突处必须明确指出。** 创始人的说法与公开文献冲突时，两种说法都写出来，说明各自依据，并告诉读者该怎么验证。
5. 创始人主动针对已知风险给出的解释，要单独核查其中的关键事实。

## 研究方法：像这个领域最强的人那样查

**不要扮演"生物专家"。** 角色扮演只会让措辞更像专家，方法没变。改为问并照做：*这个领域最会判断技术真假的人，会用什么资料、看什么、怎么交叉验证？*

### 一手资料优先（按这个顺序找）

1. **用户提供的材料**：deck、通话记录、访谈
2. **原始论文**：PubMed、bioRxiv/medRxiv。读Methods和图表，不只读摘要
3. **临床登记与监管**：ClinicalTrials.gov、中国药物临床试验登记平台、FDA/NMPA/EMA公开文件。核对注册的终点和实际报告的终点是否一致
4. **专利**：看公司真正声称"发明了什么"，往往比deck克制
5. **公司与融资**：官网、新闻稿、融资公告、创始人的论文和过往公司
6. **二手综述与媒体**：只用来找线索，不当证据

### 评估一个主张时必查的几项

- 样本量n是多少，有没有对照组，对照是什么
- 终点是真终点（生存、功能）还是替代指标（生物标志物）
- 效应量多大，不只看"显著"
- 是否被独立团队重复
- 是同行评审，还是预印本/公司自发布
- 研究阶段：体外 → 动物 → 人体早期 → 确证性试验。说明停在哪一层
- 公司只展示了好的那部分吗？没展示的数据是什么
- **对同一现象列出 2 到 3 个竞争性解释**，说明哪些证据支持哪个，而不是只讲公司想让你相信的那个

### 搜索策略

```
[topic] mechanism review
[topic] challenges limitations
[topic] vs [competing approach]
[company] [technology] preprint OR patent OR clinicaltrials
[topic] failed OR negative result OR retraction
[主题] latest news [当前年月]
[公司/分子] update [当前年份]
[模型名] new version OR benchmark [当前年份]
[断言] rebuttal OR counter-evidence [当前年份]
```

**最后两类不能省。** 主动找失败案例、撤稿和反面证据，不然只会得到宣传口径；对自己要写进去的每个关键结论，主动搜一次有没有新的反方证据，找到了就写进去，不要只写支持自己的那一半。

## 因果结构：把并列的现象整理成因果链

这一条最容易被忽略，但最影响判断。

公开资料和AI的默认输出，会把一个药的问题列成并列清单，比如"肝毒性、肾毒性、白内障、发烧"。但真实情况往往是：其中几项是同一个根因的下游结果，另外几项才是独立的问题。

**讲"这个技术有什么问题"之前，必须先画一遍因果链：**

1. 把所有已知的问题列出来
2. 判断哪些是源头，哪些是下游结果
3. 标出哪几个问题共享同一个根因
4. 标出哪些是独立路径

**这决定了"他们的方案覆盖了多少"**：如果公司解决了根因 A，那么 A 的所有下游问题跟着解决；但独立路径 B 上的问题，一点都没被覆盖。

不做这一步，就会得出"他们解决了四个问题中的一个"这种错误结论，而正确结论可能是"解决了四个中的三个，因为那三个是同一个原因"。

在正文里把这个因果结构明确画出来，读者需要看到它。

## 核心输出风格：以❓问题为单位

不用大段叙述组织知识。把内容拆成一系列❓问题，每个问题是一个独立知识模块。问题标题本身就是导航。

`❓` 在这份 skill 里是结构标记，用来指示"这里是一个问题模块"。写进交付文档时，标题就是那个不带任何符号的问句，因为用户的 CLAUDE.md 规定对外文字不用 emoji。

### 问题的设计原则

1. **从读者视角出发**：写"你自然会想到的下一个疑问"，不写"让我来讲X"。
   - 好：`市面上主流的基因疗法递送手段有哪些`
   - 好：`内吞逃逸问题是什么`
   - 差：`三、它怎么运作：机制拆解`
2. **有递进逻辑**：前一问的答案引出后一问。一屏摘要永远在最前；之后的顺序由模式决定，模式A按它的问题清单走，模式B按全景、痛点、这家公司的方案、机制、评估的顺序走。
3. **解释用分步拆解**：流程和机制一定编号；每步只说一件事；一个问题不塞两个概念；有类比就给，但类比必须准确反映机制本质，找不到好类比宁可不用。
4. **过渡自然**：必要时用一句话桥接，如"这里涉及一个关键问题：……"

### 示例格式

```
❓ 市面上主流的基因疗法递送手段有哪些

要把一段基因送进细胞里，得有个"快递员"。目前主流的有三种：

1. AAV（腺相关病毒）：一种对人无害的小病毒，把基因装进它的壳里送进细胞。
   优点是安全，缺点是壳太小装不下大基因，而且身体用过一次就会产生抗体，第二次再用就没效了
2. LNP（脂质纳米粒）：一个油性的小泡泡，把基因包在里面。
   没有病毒风险，装得下大东西，工艺也成熟，但它进了血液后基本都跑到肝脏去，送不到别的器官
3. AdV（腺病毒）：另一种病毒，效率高、装得多，但免疫反应太强，同样无法重复给药

❓ 这三种方案都卡在同一个地方：药物进了细胞，却出不来

这个问题叫"内吞逃逸"，拆开讲是三步：

1. 细胞吞进去：快递员贴到细胞表面，细胞膜把它整个包起来，形成一个小泡，拖进细胞内部
2. 小泡变酸：这个小泡本质上是细胞的"消化袋"，里面会变酸、酶会被激活，准备把吞进来的东西分解掉
3. 要逃出来：快递员必须赶在被消化掉之前，把基因从小泡里放出去，送到细胞质里才算成功

第三步的效率通常极低。结果就是大部分药物被困在小泡里，最后被当成垃圾分解掉。
```

## 配图：能画的地方都要画

文字讲机制，读者要在脑子里自己把那张图搭出来。能看见的东西不要用句子描述。

### 什么必须配图

遇到下面这几类内容，默认配图，不要问要不要：

| 内容形态 | 画什么 |
|---|---|
| 分步机制（三步以上） | 每一步画出来，步骤之间的关系用箭头或位置表达 |
| 两种或多种方案的差别 | 并排对照，同一套画法，差别用颜色或形状标出来 |
| 结构位置（哪一层、哪一段、谁包着谁） | 剖面图或分层图 |
| 时间上的竞赛或窗口 | 时间轴，把窗口和实际发生的时点都画上 |
| 因果链、根因与下游 | 左边根因右边后果，标出方案覆盖了哪几条 |
| 数量级悬殊的对比 | 按比例画，不要只写数字 |
| 分子层面改了什么 | 把序列画成可见的东西，标出被改的那一个位置 |

最后一条尤其重要。一个没有生物背景的读者读完「把某个位置的 G 改成 A」，脑子里是空的。画出来他就懂了。

### 自己画，不要去网上搜

默认自己写代码画，不要搜图。三个原因：

1. 搜来的图版权不明，而调研文档是要拿去开会、可能还要发表的
2. 风格不统一，十张图十个样子，读者要反复适应
3. 最要紧的一条：**搜来的图是按别人的叙述画的，不是按你的叙述画的。** 你文里强调的那个点，图上多半没有；图上强调的，可能跟你的结论相反

只有一种情况该用现成的图：原始论文里的关键图表，而且你要讨论的就是那张图本身。这种情况注明出处。

### 机制图的硬标准

- **标题写结论，不写主题。** 不是「三代编辑工具」，是「三代工具的差别，在于要不要把 DNA 切断」。读者扫一眼标题就拿到了要点
- **图上每个词都要是读者已经认识的词。** 正文里没解释过的术语，不能第一次出现在图上
- **颜色要有意义，并且要说明。** 红色表示什么、绿色表示什么，在副标题里一句话讲清
- **一张图只讲一件事。** 讲不完就拆成两张
- **数字写在图上，不要只写在图下面的文字里**
- 不确定的东西不要画。画出来的每个位置、每个比例都是一个断言

### 画完必须看渲染

你是盲写的，写完一定要把图渲染出来看一眼。有些问题只有看了才发现：标签压在图形上、文字超出框、线穿过标签、整张图太挤。

看完该改就改。这一步不能省。

### 图要能被改、能被评论

每个手写的文字标签都要带自己的 id，读者才能直接在图上改字、在某个部件上评论。这一点对调研文档特别有用：对方看图时的疑问会直接挂在图的那个位置上，而不是另起一段话描述「第三张图中间那个框」。

### 什么时候不要画

- 两三个数字、一个事实、一个是非判断，一句话说完就够
- 并列清单本身没有结构，画成图只是把文字排成方块
- 你自己还没想清楚的机制。图会暴露你没想清楚，这时候该回去把机制搞懂，而不是画一张模糊的图

## 模式A：学术深挖

先搜，再写。用上面的研究方法找一手资料，然后输出：

```
背景知识：[Topic名称]
```

**要回答的问题。标了「必答」的四问是科学内核，不得省略；其余按第0步的目的取舍，不要为了凑齐而每问浅尝一遍：**

- `❓ 用一句话或一个比喻理解这件事`
- `❓ 它是什么：严格定义`（必答）含"它不是什么"
- `❓ 发展历史：谁在何时发现了什么` 只讲关键转折，不写流水账。按下面「历史那一问怎么写」的办法沿约束写
- `❓ 它是怎么工作的`（必答）分步，从概念层到分子层
- `❓ 市面上现有的方案是什么` 全景与优缺点
- `❓ 为什么这件事很难`（必答）核心技术挑战，这是判断公司竞争力的基础
- `❓ 这些问题之间是什么关系`（必答）画因果链，见上面「因果结构」
- `❓ 领域现在在哪里` 最新进展、临床阶段、主要玩家、核心争议
- `❓ 这个领域里，最懂行的人怎么判断一个技术是真是假` 他们看什么指标、警惕什么信号
- `文末速查表` 10 到 15 个关键词，格式：**术语（English）**：一句话大白话定义。这是对正文解释的索引，不是解释的替代，正文里仍然要在术语第一次出现时当场讲明白

### 历史那一问怎么写：沿约束写，不要写编年史

编年史能让读者知道事情发生过，不能让他判断现在和下一步。更有用的写法是沿着约束写：每个阶段真正卡住这个领域的是什么，什么解除了它，瓶颈随后移到哪里去了。

按阶段重复这三问：

1. 这个阶段，大家按什么标准做选择，比如选靶点、选适应症、选技术路线？
2. 当时最紧的约束是什么？有什么可量化的后果？
3. 什么解除了这个约束？解除之后，稀缺的东西换成了什么？

它有三个好处：自带因果，不是并列；能解释现在为什么长这样；直接给出下一步的预测，因为瓶颈每次都是移动而不是消失。

两条要求：

- **每个阶段至少一个可量化的后果，而且有出处。** 不要只写"当时大家比较保守"，要写当时总共只有多少个靶点、某个目标花了多少年才被攻克。
- **找一个制度侧的证据。** 一个领域做什么、不做什么，往往是制度和激励决定的，不是技术决定的。制度变化前后的数字对比，是最难被反驳的证据。

这一问放在讲完机制和难点之后，不要放在正文开头当背景。有主线观点时，它就是那个观点最硬的支撑。

初稿写完后，**不要停下来问用户想追问什么**，直接进入「自动追问」。

## 模式B：Deck解读

**前提：已完成模式A，或用户确认有足够背景。**

```
业务和科学原理：[公司名称]
```

**要回答的问题：**

- `❓ [公司名]的核心技术是什么` 对应到背景知识的哪个层面
- `❓ 市面上现有方案的问题是什么` 他们攻击的痛点
- `❓ 他们的创新approach是什么` 核心机制，分步拆解
- `❓ 这个方案解决了因果链上的哪一段` 对照「因果结构」那张图，说清覆盖了什么、没覆盖什么
- `❓ 这里面真正难的是什么` know-how 和 insight 在哪。不要只做批判，真解决了难题就说清楚难在哪
- `❓ 数据说话：他们的证据有多强` 按下面的层级列出，标出夸大处
- `❓ 如果这是假的，最可能假在哪` 红队视角，列出最薄弱的 2 到 3 个环节
- `❓ 还没搞清楚的问题` 尽调必问问题，写明该问谁，以及好答案长什么样

### 证据分层表

每个关键主张都要落到这张表上，而且能回答一句话：**证据在哪一层，谁验证过。**

| 层级 | 例子 | 可信度提示 |
|---|---|---|
| 体外/细胞 | 试管或培养皿里的实验 | 离人体最远，不能直接外推 |
| 动物 | 小鼠、狗、猴 | 物种差异大，看模型是否贴近人类病症 |
| 人体早期 | I期（主要看安全性） | 能说明安全，通常不能说明有效 |
| 人体探索性 | II期 | 样本小，常有选择性报告 |
| 确证性 | III期、监管批准 | 最高证据 |
| 仅公司自述 | 未发表、无登记 | 视为待核实线索 |

### 术语翻译格式

```
❓ [术语]是什么意思，为什么重要

deck里说的：[原文]
实际意思：[完全不用专业词的大白话]
在这家公司的逻辑里：[业务含义]
```

## 观点的形成与表述

**适用范围**：目的是投资判断、写稿或公开露面时适用。目的是自己学习或解读材料时跳过这一节，先把主流共识讲准，不要为了求新偏离共识。

### 观点不是事实的推导结果

**"根据以上事实可以推出"得到的东西不是观点，是总结。** 读者，尤其是记者和投委会，听过所有常见的总结。观点是你看完这些事实之后产生的、别人没这么说过的看法，而且必须是可以被反对的。

一个能用的观点要同时满足：

- **可以被证伪**：最好带一个年份和一个具体标准，说清什么情况算它错了。
- **你知道什么会让你改变看法**：明说出来，比多举三个例子更有说服力。

公开露面时还要再加一条，见 `references/onstage.md`。

### 用户给的类比是结构要求，不是修辞

用户举例子说"我要的是这种感觉"时，他给的通常是一个结构，不是一个比喻。做法是把结构抽出来，再用本领域的事实去填。

比如用户举技术普惠：某项疗法早年只有富人用得起，后来变便宜但更贵的新疗法又出现了，到今天前者已经普及。抽出来的结构是：三个时间点，每点一个具体事物，一条单向变化的量。接下来要做的是在本领域找三个有出处的时间点和三个具体事物，而不是再写一遍那个比喻。

## 自动追问：让一个完全没有生物背景的人替用户先问完

**目的：用户不该再手动追问。** 初稿写完后，不要停下来等用户问，也不要只问一句"还想追问什么"。先自己走一遍下面的追问循环，把用户本来会追的问题答在报告里。

### 追问者是谁（用行为定义，不靠扮演）

不要写"假装你是一个外行"，那只会模仿语气。让追问者照「读者与写法」那一节描述的人平常读材料的方式去读：商科出身、看到专业词会卡住、不会停下来查、要拿这份材料去跟创始人开会。

### 他读的时候在抓什么

对每一段，他问自己两件事：**这句话我真的懂吗？我能把它讲给别人听吗？** 卡住的地方就是追问。具体抓这七类：

1. **没解释就用的词。** 任何高中生物课本以外的名词、缩写、单位。最高频，也最容易漏。
2. **跳过的步骤。** 从A直接到C，中间的B没讲。"X导致Y"，中间到底发生了什么？
3. **只讲了"是什么"，没讲"为什么偏偏是它"。** 为什么选这个靶点、这个方式？换成别的会怎样？
4. **抓大放小。** 讲了宏观结论，却略过了决定结论成立与否的关键细节：关键实验怎么做的、对照是什么、剂量多少、局限在哪。
5. **数字没有语境。** "提升40%"，相对什么？基线是多少？多少只动物？用什么方法测的？
6. **数字不知道怎么用。** 一个结论如果读者没法在电话里讲出来、没法拿它去问对方，就是写失败了。
7. **行业里的坑与争议。** 内行人知道而外行人不知道的失败教训、常见误解、没有共识的地方。

### 循环步骤

1. **按上面的方式读自己的初稿**，写下读者会卡住的地方，转成追问。
2. **给追问排序，优先级是：不补上就看不懂的，排最前。** 追问数量不设上限，但每个都必须是"读者在这里会卡住"的真问题，纯好奇的砍掉。
3. **逐个回答，需要证据就去查。** 不凭印象回答，按研究方法找一手资料。
4. **把答案放回正文它该在的位置**，写成新的❓模块或补进已有模块，不要堆成文末的"Q&A附录"。读者应该感觉这份报告本来就是这么写的。
5. **再读一遍，最多循环2轮。** 满足下面任一条就停：
   - 追问者逐段读完，每个核心机制都能复述，找不到"读到这里会卡住"的地方了
   - 新问题全是锦上添花
   - 已到2轮

### 输出时怎么交代

在报告末尾加一小节，让用户知道系统替他问过什么：

```
已替你追问过的问题
- [追问1] → 见 [位置]
- [追问2] → 见 [位置]
仍无法回答的：[问题]。原因：[公开资料查不到 / 需要向谁求证]
```

**回答不了的问题要明说**，并写清楚该向谁求证。不要编一个答案填空。

## 核查：事实、口径、来源、时效

**核心假设：把自己刚才输出的每一个具体说法，都当作可能是编的，现在去证伪它。** 不是"检查一下有没有错"。

### 一定查

- 所有带具体年份的历史事件
- 所有融资金额、轮次、投资方
- 所有引用论文（标题、期刊、作者、结论是否真的如此）
- 创始人和顾问的背景
- 关键实验数据（具体数字）
- 所有临床试验编号、阶段、状态
- **创始人口述中的关键事实**：尤其是他用来回应已知风险的那些
- **论文作者在圈内的通称**：把 Pat Walters 写成 William Walters 这类错，在内行面前是外行标记。查署名的惯用写法，不要只查姓
- **所有加减乘除**：几笔融资的加总、占比、倍数，自己再算一遍。算错一次，整段数据都会被怀疑
- **被不同文献写成不同年份的起点事件**：某个方法"哪一年提出"经常不统一。查主流引用的是哪一篇、哪一年，并说明文献口径不一致

有广泛共识的机制描述可以不查。

### 方法

- 关键数字找**两个独立来源**；只有一个来源的，标注"单一来源"
- 优先核查最容易出错、最难凭记忆的细节
- 论文要确认真实存在、没有撤稿
- 核查不到的，不要默认通过，标"未能核实"

### 来源的身份决定它的分量

"有来源"和"来源可信"是两件事。同一个数字，来自同行评议、来自监管机构、来自卖解决方案的公司，分量完全不同。

- **卖方给的数字要注明它的商业利益。** 临床试验服务商说某地入组快两到三倍，软件公司的论文说竞争方法不可靠，都要把它的生意写出来。
- **反方证据同样要查利益关系。** 不要因为一篇论文在质疑就默认它中立。质疑方卖什么，和支持方卖什么一样重要。
- **没有同行评议的头对头研究时，明说没有。** 不要把一组营销口径写成行业结论。
- **二手引用三手的，写清链条。** "某评论引用某机构的统计"和"某机构的统计"不是一回事，后者要回到原始来源核。

### 两个都对的数字，也可能不能放一起

最容易漏的一类错不是数字错，是口径错：两个数字各自都对，但统计的是不同东西，并排放就变成误导。比如一个是二期成功率，另一个是二期到三期的转化率。

做法：每组并排出现的数字，写明各自是谁统计的、统计的是什么、能不能相减或相比。不能比的，直接在文里写"这两个数字口径不同，不能直接比较"。这类错一旦被懂行的人看到，整段数据都会被怀疑。

### 时效性：和事实本身同等重要

**一个说法在两年前是对的，今天就可能是错的。** 过时的事实和编造的事实一样伤人：对外讲出去，一来显得我们连基本功课都没做，二来整段论证会被对方当场推翻。

核查对象是**每个状态类事实和每个关键结论**，每个都问三个问题：

1. **这件事最后一次更新是什么时候？** 不是"我查到的那篇文章是什么时候"，而是"这件事本身有没有更新的进展"。
2. **从那以后发生了什么？** 对准那个时间点之后再搜一次，专门找后续。
3. **我引用的是不是它的终局状态？**

必须专门搜一轮"有没有新进展"的，有这七类：

- 任何模型、技术、平台的能力评价：版本迭代很快，一年前的基准结论经常已被推翻
- 临床试验阶段与状态：有没有进入下一期、有没有终止、首例给药日期
- 监管进度：受理、优先审评、PDUFA 日期、批准与否
- 融资轮次、估值、上市状态、退市、并购
- 人物职务与所属机构
- 行业统计数字：市场规模、成功率、交易额这类数字每年都会被更新
- 任何"目前还没有人做到 X"的断言：这类断言最容易过期，必须专门搜一次反例

### 一个结论有新旧两种证据时，怎么写

不要只留新的，也不要只留旧的。写清楚这件事的演变：原来的证据是什么、什么时候的、后来出现了什么、现在是定论还是仍有争议。**"这是一场还没有结论的争论"本身就是一个有价值的结论**，比假装已经定案更可信，也更难被问倒。

### 断言被反例推翻时，收窄它，不要删掉它

"全世界还没有一款 AI 发现的药获批"这类断言，一搜就能找到反例。正确的处理不是删掉这句话，也不是硬撑，而是把定义收窄到仍然成立的那个范围，并且把反例一起写出来：

- 收窄：改成"还没有一款由生成式 AI 从头设计出来的新分子获得监管批准"。
- 带上反例：注明"AI 参与找出用途的老药另算，某某已在某年获批"。

收窄的过程本身会产生有用的东西：一旦被迫把"AI 发现"分成几级，这个分级往往比原来那句断言更值得讲。

### 输出格式和标注要求

```
Fact Check

已验证：[说法]。来源：[来源1]、[来源2]
有偏差：[说法]。正确信息：[……]，已在上文更正
错误：[说法]。正确信息：[……]，已在上文更正
未能核实：[说法]。请勿当作事实引用
```

发现错误，立刻回到正文更正，不只在这里标注。另外：

- 每个关键事实后面标**事实本身的日期**，不只是来源发表日期
- 全文开头标注资料截止日期
- 状态类事实（临床阶段、审批、融资、职务）额外标注"截至 X 年 X 月"
- 时效性存疑又核不到最新的，明确写"最新进展未能核实，截至 X 年 X 月的情况是……"

## 交叉评审：让一个没参与写作的模型挑错

自己写的东西，自己看不出哪里缺。终稿完成后，换一个模型或一个没参与写作的 agent 读一遍，让它评价质量并指出要改的地方。

**什么时候做**：完整调研做。对话里的单点追问不做，那种任务起一个 agent 过重。

### 怎么让它提得准

- **把背景同步给它**：这份东西给谁看、用在什么场合、用户想达成什么。缺了场合，它只会按通用写作标准提意见。公开露面的场合还要告诉它现场有谁。
- **把原件给它，不要给压平的导出。** 表格压成纯文本、格式丢失，它会报一堆"表格坏了"这类假错，白费一轮。
- **让它分开说两件事**：事实哪里可能错，结构哪里不够用。

### 它的意见也是待核查的说法

评审提的事实质疑，和你自己写的事实一样，要逐条核过再改。它擅长抓人名、算术、起点年份这类硬错，也会凭印象否定真实存在的事，两种都有，不能照改。

- **事实质疑在交付前核完、改完。** 它对的，改；它错的，留下并记一句为什么留。
- **结构性建议作为交付时的附注给用户。** 补哪些板块、删哪条、换哪个角度，这类建议通常比事实质疑更有价值，但要不要做是用户的决定，列出来给他挑，不要替他全做了。

## 交付与自检

目的是公开露面时，底稿交付之后还有一步：把它交给 `iceberg-evidence-doc` 走一遍 `--talk`，产出台上要说的那一份（开场钩子、主线、问答、不要说的话、可追问的点、一分钟版），那边有脚本检查有没有漏。同台场合要额外加码的几条在 `references/onstage.md`。

交付时：一屏摘要在最前，内容是核心结论、最关键的 3 个科学依据、最大的科学不确定性，读者只看这一屏也能掌握大意。已替你追问过的问题和 Fact Check 放末尾。

**文档已经交付之后再改**，改完必须重新把文档抓下来逐条断言：新说法出现一次、旧说法出现零次、结构数量对得上。只看命令返回成功不算验证。

### 自检清单

逐条过，不通过就改：

1. 有没有一个词是没解释就用了的（最高优先级）
2. 一屏摘要单独拿出来看，一个没有生物背景的人能看懂吗
3. 因果链画出来了吗，还是列了个并列清单
4. 用户给的材料都用上了吗；创始人口述与公开资料冲突的地方，有没有明确指出
5. 每个具体数字后面有来源吗；读者能拿它去问对方吗
6. 并排出现的数字口径一致吗；卖方或有商业利益一方给出的数字，注明身份了吗
7. 状态类事实查过最新进展、标了"截至 X 年 X 月"吗；"还没有人做到 X"这类断言搜过反例吗
8. 每个关键结论搜过一轮反方证据吗；有没有只做批判，没写出对方真正解决了什么
9. 尽调问题有没有写该问谁、好答案长什么样
10. 破折号、套话、黑话、给监管或国别贴标签的词，扫过一遍了吗；用户划掉的词全文清除了吗
11. 该配图的地方都配了吗；每张图都渲染出来看过一眼吗

目的是投资判断或写稿时，另加一条：主线是观点还是事实的重排，它可以被证伪吗。目的是公开露面时，另按 `references/onstage.md` 末尾那份自检再过一遍。

## 写完之后：自动接 humanizer-2

这份 skill 的产出必然偏长。读者没有生物背景，每个概念都要解释到位，而且这是 AI 写的稿子，带着 AI 的组织习惯：模板化的段落标签、摘要和正文讲同一件事、术语解释两遍。

**所以写完不直接交付，自己接着跑一遍精简。**顺序是：

1. 整份写完，过完上面的自检清单。
2. 把全文存成 `<工作目录>/draft-full.md`。这是精简那一步的信息核对基准，不能跳过。
3. **自动调用 `humanizer-2`**，输入就是 `draft-full.md`，并明确告诉它：这份稿子是 digger-v2 刚写的 AI 稿，按 AI 稿处理，不要走"判断原文是不是已经干净"那一步。
4. 交付 humanizer-2 的产出。完整版留在 `draft-full.md`，在交付说明里告诉用户它在哪，想对照可以翻。

不用等用户开口要求精简，这是默认流程的一部分。

**但不能边写边砍。**必须整份写完、自检通过、存好完整版之后，才进精简那一步。两件事在同一轮里顺序做，不是同时做。中途就开始砍的结果是两头都做不好：该解释透的因为想着要短而没写够，该删的因为还没成稿而判断不了是不是冗余。

用户明确说"只要完整版，别砍"的时候，跳过第 3 步直接交付。
